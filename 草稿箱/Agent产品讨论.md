# 跨学科产品诊断Agent · 项目思路与设计说明

文档用途：给参与协作的AI同步完整的项目背景、核心思考、产品逻辑与设计原则，用于对齐认知、集思广益、共同优化细化，而非正式产品需求文档。核心目标：一起把这个产品做深、做精、查漏补缺，重点打磨**Skill设计、数据处理逻辑、Agent调度架构**三个核心部分。

------

## 一、我为什么要做这个——底层思考与初衷

### 1. 现有工具的核心痛点

通用大模型（豆包、智谱等）和市面上的数据分析Agent，本质上都是「通用能力平台」，在专业分析场景有三个无法解决的硬伤，这也是我不直接用现成工具的原因：

1. **输出无标准、不稳定**：同样的数据输入两次，分析方法、结构、结论可能完全不同，只能当参考，不能当可靠的专业工具；
2. **质量不可控、幻觉多**：没有内置的专业校验机制，容易出现理论误用、数据编造、逻辑跳步，专业场景下出错风险高；
3. **能力碎片化、无体系**：都是单点回答问题，没有完整的方法论框架，更做不到跨学科的系统分析。

### 2. 我的核心判断：不追求「全自动」，追求「人机最优协同」

很多人做Agent都想追求“全自动化”，但我认为这是误区——AI的强项是标准化、重复性的脑力劳动，人的强项是专业判断、方法论定义、质量把控和最终决策。所以这个产品的底层逻辑是：

> 把人从繁琐的数据整理、标准化计算、流程化推理中解放出来，专注于最有价值的深度思考和业务决策；AI只做它擅长的、按规则执行的部分，绝不替代人做最终判断。

### 3. 我的差异化优势

我有工业工程+心理学+国家二级心理咨询师+经济学的跨学科背景，这个项目本质上是**把我自己的专业分析方法论，产品化成一套可复用、可编排、可评估的标准化AI能力系统**——这是纯技术背景的人做不出来的，也是和市面上所有通用分析Agent的核心区别。

------

## 二、核心产品理念——整个项目的底层原则（不可动摇）

所有设计和优化都必须遵循以下原则，不能偏离大方向：

1. **方法论驱动，而非数据驱动**先定义分析方法，再根据方法的要求定义对应的数据结构。不是“有什么数据算什么数”，而是“用什么方法，就准备什么格式的数据”。这是专业分析和凑图表的本质区别。
2. **模块化Skill架构，能力可插拔**所有专业分析能力都封装成独立的「Skill」，每个Skill是一个标准化的方法论引擎。它们可单独运行、可单独评估、可自由组合、可随时新增。业务场景和方法论完全解耦：Skill不感知自己分析的是游戏、手机还是电商，只认标准数据结构；换业务场景只需要换数据适配层，所有Skill可以直接复用。
3. 人机明确分工，边界清晰
   - **人做的事（高价值部分）**：把控数据质量、定义分析方法论、拍板最终结论、优化产品规则、判断优先级
   - **AI做的事（标准化部分）**：按规则做数据处理、结构化推理、批量计算、框架搭建、初步结论输出
   - 绝对不追求“完全自动化”，AI的定位是「专业分析助理」，不是「决策者」。
4. **质量优先于数量**小样本、高质量、深度分析，远胜过大样本、浅层次、泛泛而谈。数据宁缺毋滥，分析的深度和可靠性比覆盖的广度重要。
5. **一切皆可量化评估**每个模块、每个Skill、每个分析方法，都必须有明确的量化评估标准。拒绝“感觉有用”“效果不错”这类模糊描述，所有性能都可以用数据验证。
6. **可扩展优先于大而全**先把最小核心做扎实，再逐步扩展。新增方法、新增Skill都不能破坏现有架构，支持像插件一样快速接入。

## 三、整体产品架构——四层模块化设计

整个系统从下到上分为四层，每层职责清晰，高内聚低耦合：

```
┌─────────────────────────────────┐
│      输出交互层                  │ 结构化报告 + 置信度标注 + 人工修正闭环
├─────────────────────────────────┤
│      核心调度层（Agent大脑）      │ 任务拆解 · Skill路由 · 流程编排 · 结果校验
├─────────────────────────────────┤
│  工业工程Skill │ 心理学Skill │ 经济学Skill │  独立专业方法论引擎，方法注册制
├─────────────────────────────────┤
│           数据层                 │ 原始素材 → 标准数据中台 → Skill专属数据集
└─────────────────────────────────┘
```

------

## 四、核心模块详细设计思路

### 1. 数据层——最具差异化的设计，也是分析质量的根基

这部分是我特意设计的，和绝大多数Agent的思路都不一样，核心是**主动避开AI的短板，用人工保障数据质量**。

#### （1）数据获取：人工主导，AI辅助

- **不做Agent自动爬取/搜索**：不用Agent去做网页浏览、数据抓取。原因是当前通用Agent的网页能力极弱，面对反爬、登录、动态页面、PDF内嵌内容成功率很低，数据质量不可控，调试成本远高于收益。
- **实际做法**：人用通用大模型（豆包、智谱等）辅助找数据源、提取网页/文档/表格里的关键信息，人工整理分类、命名存储。支持所有格式：网页、PDF、Word、Excel、Markdown等。
- **核心逻辑**：数据质量是分析的生命线。人工花10分钟整理高质量数据，比花10小时调试Agent爬取低质量数据，性价比高10倍。

#### （2）两层数据架构：先统一，再拆分

遵循「方法论驱动数据」的原则，分成两层处理，避免重复劳动，同时保证每个Skill的数据适配性：

- **第一层：标准数据中台（通用层）**所有原始数据都先清洗成统一的标准格式，定义通用元数据规范（比如：实体ID、时间戳、事件类型、核心数值/文本字段）。这一层只做最基础的格式统一、字段标准化、异常标记，不做任何分析加工。
- **第二层：Skill专属数据集（适配层）**每个Skill根据自己的分析方法，从中台标准数据里加工出自己需要的专属数据结构。比如心理学Skill需要把文本转成语义标签，工业工程Skill需要把事件转成流程节点。
- **扩展逻辑**：新增一个分析方法，只需要新增对应的数据处理逻辑，不影响其他Skill，也不改动底层中台。

### 2. Skill层——产品的核心竞争力

Skill的本质是「把专业方法论封装成标准化的AI能力」，是整个项目的护城河。

#### （1）设计规则：方法注册制

每个Skill内部的所有分析方法，都像插件一样注册管理，每项方法必须明确定义：

- 方法名称与适用场景
- 输入数据结构（必须包含的字段）
- 输出数据结构（输出的维度和结论）
- 标准推理步骤
- 置信度判断规则

#### （2）三个核心Skill（工具暂定待讨论）

| Skill名称     | 核心定位             | 核心分析工具                                               | 解决的问题                                                   |
| ------------- | -------------------- | ---------------------------------------------------------- | ------------------------------------------------------------ |
| 工业工程Skill | 全链路流程与系统诊断 | 流程程序分析法、ECRS优化原则、TOC约束理论、价值流图等      | 拆解完整流程、识别系统瓶颈、定位非增值环节、给出系统优化方向 |
| 心理学Skill   | 行为归因与需求挖掘   | 计划行为理论、自我决定理论、认知负荷理论、期望不一致理论等 | 解释行为背后的动机、识别需求本质、诊断体验障碍、挖掘深层诉求 |
| 经济学Skill   | 价值量化与决策辅助   | 成本收益分析、机会成本评估、边际效用分析、沉没成本识别等   | 量化问题的经济损失、测算方案的投入产出、给选项做优先级排序   |

#### （3）共同要求

- 每个Skill完全独立封装，输入输出标准统一；
- 不包含任何业务属性，和具体行业/产品完全解耦；
- 所有推理严格基于内置方法和输入数据，禁止自由发挥、禁止引入外部知识。

### 3. 调度层——Agent的大脑

调度层本身不做专业分析，只做四件事：任务拆解、Skill路由、流程编排、结果校验。

- 调度策略：规则为主，灵活为辅
  - 80%的标准场景：预设固定工作流。比如「全链路诊断任务」，固定执行「工业工程找瓶颈 → 心理学做归因 → 经济学算价值」的串行流程，每个环节调用哪些方法都提前定好，保证稳定性。
  - 20%的非标场景：由AI根据方法注册信息，自动匹配合适的方法组合，但必须输出「调度理由」，接受人工校验。
- **交叉校验机制**：重要结论必须用至少两个维度的结果交叉验证，结论一致则正常输出，不一致则标记「存疑」并说明原因，推给人工判断。

### 4. 输出交互层

- 输出**结构化的深度分析半成品**：包含数据支撑、方法依据、计算过程、初步结论、备选方案、置信度标注，所有结论可追溯到原始数据。
- 保留**人工修正闭环**：人可以对结论、优先级、归因进行调整修正，AI可以根据人工反馈重新生成对应部分。
- **核心原则**：AI只给参考和支撑，最终结论和决策一定由人来拍板。

## 五、最终价值与定位

这个产品不是“又一个数据分析AI”，而是一套**「人机协同的专业分析工作系统」**。它的价值不是替代人做分析，而是把分析工作里所有标准化、重复性、流程化的脑力劳动全部承接过来，让人只做最核心的：判断结论是否合理、结合业务经验拍板、做最终的决策和优化。

最终产出的不是一份AI写的报告，而是**由AI搭好完整框架、算好所有数据、铺好所有逻辑，最终由人注入深度思考和业务判断的高质量分析成品**。

## 六、当前阶段与协作方向

### 当前进展

已经确定整体架构、核心理念和三个核心Skill的方向，准备从单个Skill开始落地验证，逐步跑通全流程。

### 我们的目标

不是做一个调API的demo，是做一套**有方法论、有架构、可评估、可扩展**的专业分析系统，真正体现产品思维和跨学科的深度。

### 希望一起优化的方向

1. 各个Skill的方法库细化、推理逻辑优化、Prompt策略设计
2. 数据层的标准规范细化、两层架构的落地细节
3. 调度层的编排策略、校验机制、异常处理设计
4. 每个Skill的量化评估体系、评测集构建方法
5. 查漏补缺：指出我没考虑到的风险、漏洞和优化点

所有优化建议请基于以上核心原则，不要偏离「模块化Skill架构、方法论驱动、人机协同、可量化评估」的大方向。
