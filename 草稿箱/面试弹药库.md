# 面试弹药库 · Agent 产品实践体会清单

**用途**：沉淀"做产品分析 Agent 过程中真正体会到、且能讲清为什么"的认知资产，用于实习面试。持续补充维护，**不进 PRD**（PRD 讲产品，本文档讲认知，混放会互相污染）。

**维护规则**：
1. 条目只增不删，编号 K01 起连续递增；
2. 每条必须四件套齐全：**内核一句话 / 出处判例（真实证据）/ 面试话术 / 反面（没有这条会怎样）**——无判例支撑的空洞体会在本库没有资格存在；
3. 新体会的产生时机：实跑踩坑后、缺陷归因后、与他人讨论被问住后；
4. 每条体量控制在"面试现场 90 秒能讲完"。

---

## K01 · 方法唯一源头论：数据需求由方法推导，不是有什么数据算什么数

- **内核**：先定义分析方法，再由方法反推输入 schema，禁止反向流动。
- **出处判例**：设计总案第 2 节确立；M03 全程实证——表 A-G 每个字段都能指回 STEP 0-6 的某一步消费点。
- **面试话术**："市面上大多数分析 Agent 是'用户给什么数据就凑什么图表'，我的系统反过来：每个方法先声明数据契约，采集清单、前置检查、降级触发全部由契约推导。图表类型也是方法预先绑定的，不允许模型看数据即兴选型。"
- **反面**：数据驱动凑方法 → 输出不稳定，同样的数据跑两次结论不同，这是通用大模型做专业分析被诟病的根因。

## K02 · 验证左移：业务逻辑逐层验证的成本，远低于全量做完再验

- **内核**：缺陷发现越晚，修复成本指数级放大；每一层（schema→中间表→诊断项→报告）都要有自己的验证关卡。
- **出处判例**：M03 的 24 条缺陷全部在单包内爆掉——若九包量产后才发现六件套结构有误，返工代价是九倍（打样件逻辑）。
- **面试话术**："我没有把九方法全写完再测，而是 M03 一个包打样、五轮实跑、24 条缺陷闭环、确认结构成立后才量产。这和测试左移是同一个思想，只是发生在方法论工程里。"
- **反面**：批量生产未验证的结构 → 结构性返工，缺陷跨包复制。

## K03 · 缺陷日志是 Agent 产品最值钱的资产，不是负面记录

- **内核**：对同类任务提炼通用错误模式，固化为规则/判例/flag，组织记忆因此可累积。
- **出处判例**：M03 缺陷日志 24 条（只增不删、每条三件套：出处+修复+验证）；S 系列编号已成协作语言；7 条判例（如 C04 证伪判例）被后续方法包直接援引。
- **面试话术**："我的缺陷日志条目只增不删。每条缺陷修复后提炼成通用规则进注册表——比如'假设清单必须包含所有被固定的变量'这条，来自一次反推结论稳健性被高估的教训。方法包换了一个又一个，这些规则是沉淀下来的东西。"
- **反面**：踩坑→修复→遗忘→换个人/换个包再踩一遍，团队经验无法复利。

## K04 · 数据进大模型前必须过四层校验，且四层抓的东西互不重叠

- **内核**：L1 代码查格式 / L2 代码查不变式 / L3 LLM 查语义 / L4 人裁决争议——每层有明确的"抓不到什么"。
- **出处判例**：数据 QC 规程 v1.0（已冻结）；三只松鼠 29 期财务序列双路径取数差 27% 被 L2 跨源碰撞引擎抓到；Model S 时点错位被 L3 溯源核验抓到。
- **面试话术**："L1 抓不住内容错误，L2 抓不住'算术全对但意思错'，所以必须有 L3 语义层点开 URL 读原文；L3 解决不了的争议留给人。每层的能力边界是显式写出来的，不是含糊的'AI 审核'。"
- **反面**：单层校验 → 要么漏语义错误（数据脏），要么漏格式错误（程序崩），且出了问题无法归因到层。

## K05 · 执行形态是架构决策，不是 prompt 技巧

- **内核**：单轮还是分轮，由负载结构（算术密度×生成预演×纪律耦合）决定；中间表落盘=状态外化，是长任务 Agent 的通用解法。
- **出处判例**：S15——两版 prompt patch 均无法阻止 20 分钟超时，根因是一次性大 prompt 形态；改三轮切法（算术轮/判断轮/冲突装配轮）后 5-10 分钟级完成。S20 反向判例——轻负载方法单响应连跑三轮质量无损，单轮直出合法化。两条判例合成原则：**负载决定形态，形态由编排层声明**。
- **面试话术**："业界讲 Agent 都在讲 ReAct、function calling，我踩过的坑是执行形态：同一个方法包，一次性跑超时两次，切成三轮带中间表落盘就稳了。这其实就是 context engineering 的本质——管理模型每一轮看到什么。"
- **反面**：把超时当归因于"模型不行"→ 换模型、加 prompt 恳求，全部无效，因为病在形态不在模型。

## K06 · 输出偏离 schema 时，先查信息可达性，别急着怪模型

- **内核**：模型只能利用窗口内可见的信息；输出缺字段，第一嫌疑人是"该信息是否进入了本轮上下文"。
- **出处判例**：S17——R3 prompt 写"同前 schema"指向未贴入窗口的文档，模型输出字段名正确但结构压缩。归因裁定：缺陷在执行包，模型侧零责任（D5 归因判例）。
- **面试话术**："我建立了一条归因纪律：输出偏离时先查信息可达性再查模型能力。后来统计，大多数'模型不行'其实是'模型看不到它需要的东西'。每轮 prompt 必须自携完整 schema，禁止悬空引用。"
- **反面**：错怪模型 → 花大钱换更强的模型，问题原样存在。

## K07 · 诚实性是工程实现，不是 prompt 恳求

- **内核**：让 Agent"知道自己什么时候不知道"，靠的是降级路径+flag 枚举+禁编造条款的机械执行，不是"请不要编造"四个字。
- **出处判例**：M03 六条 flag 全部实弹验证；M05 供给约束触发 SUPPLY_CAPPED 则弹性分析终止转定性登记；capture_ratio 区间跨零→"方向不可判"禁止中点结论（来自一次真实的中点当确定值的 D3 缺陷）。
- **面试话术**："我的系统里每个方法都有降级路径枚举表：数据缺到什么程度、触发哪个 flag、降级成什么输出形态，全是预定义的。'未量化+原因'是合法输出，编数字是阻断级缺陷。宁可输出诚实的不确定性，不输出虚假的精确。"
- **反面**：模型硬答 → 幻觉数字进入报告 → 专业场景下一次错就失去信任。

## K08 · 人机分工的边界画在"判断"上，不画在"执行"上

- **内核**：算术、校验、路由、格式全给代码；语义核验给独立 QC 模型；只有争议裁决和最终结论归人。
- **出处判例**：QC 四层栈 L1-L4 分工；受控 vs 开放对照判例——同一模型，禁联网受控模式输出纯度显著更高；交叉校验机制（不一致标"存疑"推人工）。
- **面试话术**："我不追求全自动。AI 承接标准化脑力劳动，人只做两件事：裁决冲突、拍板结论。边界是经过实测的——开放模式下模型自己补的数据，质量就是不如人工建档后受控喂进去的。"
- **反面**：全自动幻想 → Agent 自由发挥，质量不可控；全人工 → 失去规模化意义。

## K09 · 方法资产是数据不是代码：新增方法=加文件夹，引擎零改动

- **内核**：skill.md+schema+chart binding+eval 是纯数据资产，进注册表；执行引擎只认统一骨架，不感知具体方法。
- **出处判例**：设计总案三层架构；M04 量产时直接继承 M03 全套纪律（S1-S19 条款+分轮协议），零引擎改动。
- **面试话术**："我的方法包是文件夹不是代码——理论内核、输入输出契约、图表绑定、评测用例全是声明式的。新增第十个方法不需要动一行引擎代码，这是插件化的真实含义。"
- **反面**：方法逻辑硬编码 → 每加一个方法改引擎，回归风险随方法数线性增长。

## K10 · 评测不是"像不像专家"，是三层：共识覆盖 + 冲突裁决 + 增量发现

- **内核**：共识覆盖是防守（对得上主流分析）；冲突裁决是裁判力（对不上时谁对，可能专家对也可能我对）；增量发现是进攻（专家未见而我见且可验证）。
- **出处判例**：M03 冻结条件（claim 覆盖率≥70%+novelty≥1）；CONF-01——行业广泛传播的数据误挂被官方数据算术证伪，若只做"对得上=好"，这次胜利反而被判失败。
- **面试话术**："拿 Agent 产出和市场已有分析对照时，我把结果分三档：覆盖、冲突、增量。冲突档最值钱——M03 实跑时证伪过一条行业级的数据误挂，如果评测只看'和专家一不一致'，这种真洞察会被当成错误杀掉。"
- **反面**：单一覆盖度指标 → 系统被训练成复读机，且媒体共识本身的立场偏差（投放关系）无人裁决。
