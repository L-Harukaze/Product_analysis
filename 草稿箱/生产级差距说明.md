# 生产级差距说明 · V1（面试演示版）→ 生产级

**用途**：结构化登记 V1 每个环节的简化决策，以及"生产级应该做到什么程度"。回答面试问题"你这个离真实产品差在哪"的标准答案库。**每条差距必须是已知权衡，不允许存在"没想到"的差距。**

**填写规范**：每条四要素——`V1 怎么做 / 生产级应做到 / 差距影响 / 补齐路径`。环节编号与 PRD 架构章节对齐。

**状态图例**：🔵 V1 已按简化方案实施 ｜ ⚪ 规划中未实施

---

## 一、数据层

### G1.1 数据采集方式 🔵
- **V1**：人 + 豆包找数，豆包按整理 prompt 模板格式化为 input.schema，代码 L1 校验后入档（SQLite）。
- **生产级**：MCP 结构化指标自动采集（iFinD/EDB 等）+ 公告原文自动归档 + 多源冗余（单一 MCP 依赖是总案未决问题 7）。
- **差距影响**：每换一个产品约 20% 人工建档工作量；数据时效靠人维护。
- **补齐路径**：采集 SOP → MCP 接口适配层 → 人工抽检比例递减。

### G1.2 数据 QC 🔵
- **V1**：L1/L2 代码校验全量 + L3 语义 QC 抽样（承重数字必检）+ L4 人裁决。
- **生产级**：L3 全量且**异模型异上下文**执行（QC 独立性原则）；QC 记录全量留痕可审计。
- **差距影响**：非承重数字的语义错误可能漏网，影响长尾结论可靠性。
- **补齐路径**：QC agent 独立部署 + 校验报告入档。

### G1.3 方法包验证深度 🔵
- **V1**：受控轮单轮通过即视为可用；降级 flag 覆盖式检查非全实弹；claim 集轻量版（3-5 来源）。
- **生产级**：五条件冻结流程（连续 2 轮 D1=D2=D5=0 / 覆盖率≥70% / novelty≥1 / 降级路径全实弹 / 图表四查）——M03 实证的标准。
- **差距影响**：个别方法包可能存在未暴露的事实错/机制错；降级路径未实弹的可能首次触发即异常。
- **补齐路径**：量产稳定后逐包补冻结流程；缺陷债务登记上限并跟踪。**（此条是 V1 最大的已知风险，面试必须主动讲）**

## 二、方法层

### G2.1 方法覆盖 🔵
- **V1**：经济学 10 包（M01-M09 + S4 蛛网代表），覆盖 7 问题域；虚拟商品/订阅服务走形态字典论证不实跑；平台双边市场仅预留 F7 位。
- **生产级**：心理学 Skill（锚定→行为诊断全栈）、工业工程 Skill（流程/TCO 深化）接入；游戏/SaaS 品类实跑验证。
- **差距影响**：诊断视角单一（纯经济学），行为归因与流程诊断缺失。
- **补齐路径**：Skill 接口已按插件化设计，新增 Skill=新增方法包文件夹组。

### G2.2 品类形态字典 🔵
- **V1**：汽车/快消/大宗/虚拟四行核心变形规则，由 M01/M03 实证反推。
- **生产级**：字典经 ≥3 品类实跑校准，每行变形规则有实证出处；化妆品/服饰/家电等行补全。
- **差距影响**：未实跑品类的变形规则是推断，首次实跑可能大面积触发降级。
- **补齐路径**：第二、三产品实跑（三只松鼠→红米 K80→可选第三品类）逐行校准。

## 三、调度与编排层

### G3.1 执行编排 🔵
- **V1**：单进程顺序执行；分轮协议由编排器自动调度（R1/R2/R3 + 中间表落盘 SQLite/文件）；FastAPI 后台任务 + 前端轮询进度。
- **生产级**：任务队列（Celery/Redis 等）+ 方法级并发（九方法并行）+ 断点续跑 + 失败重试 + 执行预算字段强制超时（S14 教训的基础设施化）。
- **差距影响**：全方法池跑一次为串行分钟级；中途失败需整包重跑。
- **补齐路径**：中间表已落盘，断点续跑是低垂果实；任务队列按需引入。

### G3.2 指纹路由 🔵
- **V1**：F1-F6 规则表直查 + 边界 LLM 仲裁（强制输出理由）+ 仲裁结果落库固化保幂等。
- **生产级**：路由决策全量审计日志；仲裁准确率评测集；指纹维度有效性回顾机制（维度增删的受控变更）。
- **差距影响**：仲裁质量依赖单次 LLM 判断，无准确率度量；同产品重新路由的幂等靠落库纪律而非工程强制。
- **补齐路径**：仲裁案例库累积 → 评测集 → 规则表迭代固化（②区案例固化进①区）。

### G3.3 报告装配 🔵
- **V1**：规则化装配——诊断项按 7 问题域归位 + 分类学归位 + 排序；跨方法冲突按证据强度仲裁留痕。
- **生产级**：货币化汇总统一折算口径（总案未决问题 3：CBA 统一折算 vs 分方法各自货币化）；交叉增益置信升级的实证校准。
- **差距影响**：缺陷账单（X 亿/年）口径可能夸大，V1 阶段**选择不输出汇总货币化数字，只在单方法内货币化**——规避夸大风险。
- **补齐路径**：货币化口径经第二产品实证后定稿再开放汇总输出。

### G3.4 品类基线覆盖 🔵
- **V1**：指纹判定 L2 定量层（ARCHITECTURE 7.1）依赖品类基线表（表H），仅建手机+零食两品类；SU7 走指纹预置固化。基线值与档位边界值静态人工维护。
- **生产级**：品类随接入逐步建基线（每品类半小时级豆包工作量）；价格分布/更换周期等时效字段定期更新；档位边界值经多品类实证校准。
- **差距影响**：未建基线品类的 F1 退化为 L3 无锚点仲裁（确定性回退）；基线过期导致 F1 档位误判。
- **补齐路径**：新品类首次诊断前随采集 SOP 建基线；基线更新纳入档案维护例程。

### G3.5 跨方法矛盾检测召回 🔵
- **V1**：装配层跨方法冲突检测由 LLM 提出 conflict_candidates（ARCHITECTURE 12.1），代码按证据强度仲裁（同强度平局回交 Owner）。
- **生产级**：结构化矛盾模式库（可判定矛盾类型清单化，规则前置检测）；LLM 检测召回率评测集。
- **差距影响**：语义矛盾的发现依赖 LLM 召回，无完备性保证——漏检矛盾以"未被发现"形式静默进入报告（T6 管"已发现的失败必须可见"，不管发现率）。
- **补齐路径**：eval 用例随量产积累矛盾样本；高频矛盾模式固化进规则检测层。

## 四、评测层

### G4.1 验证方法 🔵
- **V1**：claim 集三层对照（覆盖/冲突/增量），3-5 来源 × 3-5 论断，来源立场标注。
- **生产级**：外部专家 claim 集扩样 + Owner 独立答案常态化（防复读专家层失效）+ 增量发现判定标准定稿（总案未决问题 9）。
- **差距影响**：小样本 claim 集的覆盖率数字波动大，70% 阈值指示性弱。
- **补齐路径**：每次实跑扩充 claim 库；Owner 独立答案每包一页纸。

### G4.2 持续质量 🔵
- **V1**：缺陷日志维护（条目只增不删）；无自动化回归。
- **生产级**：方法包 eval 用例集 + 变更触发自动回归（schema/变体集/模板库改动=受控变更需批准+回归）。
- **差距影响**：改一处纪律条款可能静默影响多包，V1 靠人盯。
- **补齐路径**：eval 用例随量产逐包积累，回归脚本化。

## 五、工程与合规

### G5.1 部署与访问 🔵
- **V1**：本地单机运行，支持局域网访问演示；单用户。
- **生产级**：多用户隔离不做（项目明确决策），但需访问控制、操作审计、数据备份策略。
- **差距影响**：演示环境无权限概念，数据档案可被误改。
- **补齐路径**：档案写操作收口到 API + 变更日志。

### G5.2 数据合规 ⚪
- **V1**：来源 URL 全留痕，演示用途。
- **生产级**：数据源版权/使用条款审查（iFinD/EDB 等授权范围）、报告引用合规。
- **差距影响**：对外发布报告有版权风险。
- **补齐路径**：采购数据源商用授权；引用规范审查。
