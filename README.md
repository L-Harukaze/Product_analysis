# AIAC 产品研判系统

> 输入一个具体产品（如红米 K80），输出一份**跨学科视角的结构化诊断报告**——按七个问题域组织，每条诊断含「事实·机制·量化·处方」四层，所有承重数字可溯源到原始数据，图表由方法预绑定生成。

## 为什么做这个

市面上的通用大模型和数据分析 Agent，本质都是「通用能力平台」，在专业分析场景有三个绕不开的硬伤：

1. **输出无标准、不稳定**——同样的数据输入两次，方法、结构、结论可能完全不同，只能当参考，当不了可靠的专业工具；
2. **质量不可控、幻觉多**——没有内置的专业校验机制，理论误用、数据编造、逻辑跳步频发；
3. **能力碎片化、无体系**——单点回答问题，没有完整方法论框架，更做不到跨学科的系统分析。

我的核心判断是：**不追求「全自动」，追求「人机最优协同」**。AI 的强项是标准化、重复性的脑力劳动；人的强项是专业判断、方法论定义、质量把控和最终决策。所以这个项目的底层逻辑是——把人从繁琐的数据整理与流程化推理中解放出来，专注最有价值的深度思考与业务决策；AI 只做它擅长的、按规则执行的部分，**绝不替代人做最终判断**。

我的差异化在于跨学科背景：**工业工程 + 心理学（国家二级心理咨询师）+ 经济学**。这个项目本质上是**把我自己的专业分析方法论，产品化成一套可复用、可编排、可评估的标准化 AI 能力系统**——这是纯技术背景做不出来的，也是它与所有通用分析 Agent 的根本区别。

## 核心思想

| # | 原则 | 一句话 |
|---|---|---|
| 1 | 方法论驱动，非数据驱动 | 先定义分析方法，再据此定义数据结构；不是"有什么数据算什么数"，而是"用什么方法，就准备什么格式的数据" |
| 2 | 问题域为骨架，方法为填充，指纹为选择器 | 诊断**完整性**由 7 域保证，**适配性**由路由保证，**扩展性**由形态字典保证 |
| 3 | 方法资产是数据不是代码 | 新增方法 = 新增一个文件夹，执行引擎零改动 |
| 4 | 诚实性是工程实现 | flag 枚举 + 降级路径 + 禁编造条款；"未量化 + 原因"是合法输出 |
| 5 | 四层诊断结构强制 | 每条结论必须含 事实 → 机制 → 量化 → 处方 四层，代码校验，缺一即阻断 |
| 6 | 人机分工画在判断上 | 执行全给代码，语义质检给异模型，裁决归人 |

## 方法论地图：七问 × 三学科

诊断完整性靠 7 个**问题域**保证（品类无关的骨架）；每个域挂载一个**方法包**（专业化填充）；产品指纹决定激活哪条方法、用什么形态。

| 域 | 商业问题 | 方法包 | 主学科 | 理论支柱 |
|---|---|---|---|---|
| D1 市场结构 | 竞争位置稳不稳、定价权在谁 | M01 市场结构 | 经济学 | 产业组织、市场集中度 |
| D2 定价机制 | 怎么从用户身上收钱 | M03 版本阶梯 | 经济学 + 心理学 | Mussa-Rosen 二度价格歧视、自我选择 |
| D2 定价机制 | （参照锚定路径） | M04 参照价锚定 | 心理学 | Tversky 锚定效应、参照依赖 |
| D3 需求响应 | 降价 / 竞品 / 政策能撬动多少量 | M05 交叉价格弹性 | 经济学 | 微观需求弹性 |
| D3 需求响应 | （政策冲击路径） | M08 政策断点 | 经济学 | 断点回归、政策事件研究 |
| D4 成本动态 | 成本会不会越来越低 | M02 学习曲线 | 工业工程 | Wright 学习曲线、进程学习 |
| D4 成本动态 | （同质品周期路径） | S4 供给时序 | 工业工程 + 经济学 | 蛛网理论、产能滞后 |
| D5 用户价值量化 | 用户买它划不划算 | M06 总持有成本 | 工业工程 + 经济学 | TCO 全生命周期成本 |
| D5 用户价值量化 | （耐用/保值路径） | M09 金融杠杆 | 经济学 | 残值率、金融杠杆 |
| D6 信息结构 | 用户为什么信、信息不对称折价多少 | M07 信息结构 | 经济学 + 心理学 | 信息不对称、信号理论、信任资产 |

> **三学科的分工不是标签，是设计**：经济学方法算"该是多少"，心理学方法解释"为什么用户接受/拒绝这个数"，工业工程方法追踪"这个数随生产/时间怎么变"。三者交叉处才有完整的产品诊断。

## 一条诊断的生命周期

```
① 指纹判定（F1-F6 六维）→ 路由 → 激活矩阵{问题域 × 方法 × 形态}
② 采集 prompt 生成 → 数据需求按方法 schema 推导（不是"有什么算什么"）
③ 数据提交 → L1 代码校验（不合格打回并定位到行/字段）→ 入档 SQLite
④ 方法池执行（分轮协议 + 中间表落盘 + 四项静态校验）→ 诊断项 + 图表数据
⑤ 报告装配（按 7 域分域同构）→ 结构化报告
⑥ L3 QC 异模型质检（per-method 批量、不拦截、人裁决）+ L2 冲突裁决闭环
⑦ Owner 对照已有分析做三层评测（覆盖 / 冲突 / 增量）
```

关键工程机制：

- **三级漏斗防幻觉**：L1 代码静态校验 → L2 不变式检查（算术闭合/口径混算/跨源碰撞）→ L3 异模型语义质检
- **冲突裁决闭环**：跨源数据碰撞 → Owner 裁决（维持 / 手动改数走事务 B 重提交）→ 幂等落库
- **诚实降级**：flag 枚举 + 显式降级路径，"未量化 + 原因"是合法输出而非缺陷
- **全留痕**：每次 LLM 调用进 `llm_call_logs`（token / 延迟 / 终态），可复盘可审计

## 技术架构

四层解耦设计：

```
┌─────────────────────────────────────┐
│  输出交互层（React + Ant Design）   │ 结构化报告 + 四层诊断卡 + QC 裁决 + claims 评测
├─────────────────────────────────────┤
│  核心调度层（FastAPI Agent）         │ 事务编排 · 状态机 · 路由 · 装配 · QC
├──────────┬──────────┬──────────────┤
│ 经济学包 │ 心理学包 │ 工业工程包    │ 方法注册制：新增方法=新增文件夹，引擎零分支
├──────────┴──────────┴──────────────┤
│  数据层（SQLite + JSON 行模式）      │ 12 表逻辑 schema · 来源/置信/口径三件套
└─────────────────────────────────────┘
```

| 层 | 技术选型 |
|---|---|
| 后端 | FastAPI · SQLite（WAL + busy_timeout）· 全 async |
| 执行 LLM | 阿里云百炼 qwen3.8-max（executor + arbiter 双角色） |
| 质检 LLM | DeepSeek（异模型，G1.2 异构保证独立性） |
| 前端 | React 18 · TypeScript · Vite · Ant Design · ECharts |
| 方法资产 | YAML + Markdown（数据不是代码，T2 引擎零方法分支） |

完整施工图纸见 [`ARCHITECTURE.md`](./ARCHITECTURE.md)（十四章定稿：五事务两断点状态机 / 12 表逻辑 schema / 13 章契约 / T1-T7 总则 / P 系列约束）。

## 快速开始

### 依赖

```bash
# 后端
cd backend
python -m venv .venv && .venv\Scripts\activate      # Windows
pip install -r requirements.txt

# 前端
cd ../frontend
npm install
```

### 配置密钥

在 `backend/.env` 填入（参照 `.env.example`，密钥**绝不入库**）：

```
LLM_EXECUTOR_KEY=sk-...   # 百炼 executor
LLM_ARBITER_KEY=sk-...    # 百炼 arbiter
LLM_QC_KEY=sk-...         # DeepSeek
```

### 启动

```bash
# 后端（默认 127.0.0.1:8000）
cd backend && uvicorn app.main:app --reload

# 前端（默认 5173，已配 /api 代理到后端）
cd frontend && npm run dev
```

### 演示路径

打开 http://localhost:5173，输入「红米 K80」→ 高级选项可贴产品背景 → 系统生成采集 prompt → 粘给豆包取数 → 粘回系统 → L1 校验入档 → 点执行 → 约 2 分钟出 7 域结构化报告。

> 红米 K80 的完整档案已预建档，可跳过取数环节直接从执行起步。

## 项目状态与版本

本项目用 git 工作流管理版本演进，主线为 `main`：

| 版本 | 内容 |
|---|---|
| `main` | 完整版（全量 7 方法 × 三轮分轮 × 推理模型），方法论资产冻结 |
| `tag old_version` | 完整版书签（备注：超时问题未解决——思考模式 × 大配方超出 600s 物理预算） |
| `flash` 分支 | **演示档**：A/B 实验裁决后六刀减载——关思考模式 / 白名单 3 方法 / 单轮直出 / 切片 5 行 / 并发 3 / 装配并发化，全量冒烟 1.2 分钟跑通 |

> flash 档减的是**配置量与调用次数，不是架构**——方法包体系、四层诊断、QC 异模型、裁决闭环一概不动。这本身就是架构分层价值的兑现：减载 = 改 YAML，引擎零分支。详见 [`flash改动方案.md`](./flash改动方案.md)。

每一处简化都登记在《生产级差距说明》中，能回答"离生产级差在哪、怎么补"——这是 V1 的成功标准之一。
